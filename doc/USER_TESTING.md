# 用户验收手册

本文用于发布前验证“WiFi传书”Calibre 插件。自动化测试负责打包、插件加载和模拟上传；手机端实际收书与打开 EPUB 由用户完成。

## 准备条件

- macOS 已安装 Calibre，命令行目录已加入 `PATH`
- 手机和电脑连接同一局域网
- 多看阅读已开启 WiFi 传书，并显示可访问的 HTTP 地址
- Calibre 书库中准备以下样本：
  - 一本普通 EPUB
  - 两本以上 EPUB
  - 一本较大的 EPUB
  - 一本没有 EPUB 格式的书籍

## 发布前自动验证

```bash
make verify
```

通过标准：终端最后显示 `VERIFY OK`。该命令会完成：

1. 读取 `src/__init__.py` 版本号并生成版本化 ZIP
2. 检查 Python 语法、必要文件和 ZIP 完整性
3. 使用临时 `CALIBRE_CONFIG_DIRECTORY` 隔离真实配置
4. 测试 `calibre-customize -b src` 开发构建流程
5. 测试发布 ZIP 的全新安装、插件导入和模拟 `/files` 上传

## 安装到日常 Calibre

先正常退出 Calibre，再执行：

```bash
make install
```

安装脚本会先完整验证，再备份当前名称和旧名称插件，移除旧名称“多看阅读WiFi传书”，最后安装刚通过验证的版本化 ZIP，确保日常安装与发布产物完全一致。已有设备配置继续使用原配置键。

如明确允许脚本先请求 Calibre 关闭，可执行：

```bash
make install-shutdown
```

注意：强制关闭可能中断正在运行的 Calibre 任务。

## 启动用户验收

```bash
make user-test
```

该命令通过 `calibre-debug -g` 启动 Calibre，并把控制台输出保存到 `dist/logs/`。

## 验收项目

### 连接

- 在约 700×420 的原生设备管理器中添加、编辑、删除和命名设备，重启仍保留默认设备及多选收件人
- 设备可重名，但勾选、编辑、删除和设默认始终作用于正确行
- 旧版真实地址只迁移一次，默认占位地址不会成为设备
- 输入多看显示的地址，不带 `http://` 时插件能自动补全
- 正确地址显示连接成功
- 错误 IP、错误端口和已关闭的 WiFi 传书服务能显示明确错误
- 测试连接期间界面没有卡死
- 自动查找复用当前设备端口，只发现当前 Wi-Fi 子网内同时含两个多看指纹的服务；没有当前设备时正确询问多看显示的端口
- 管理器内点击「测试 / 自动查找」后，发现项回填到同一个管理器并自动勾选；工具栏直接查找则打开预填管理器
- 同端口多个不可达设备不会都映射到同一主机；歧义候选留给管理器手动命名、编辑和保存
- 确认 Close 丢弃管理器修改，Save 才提交；自动查找不扫描其他端口、不自动保存或上传
- macOS 在 Wi-Fi 与有线网同时连接时仍从 Wi-Fi 送达；无法绑定时显示明确错误
- Windows/Linux 能直连并发送到可达的已保存地址；不可达时明确说明不支持自动子网查找并要求手动修正

### 传输

- 单本 EPUB 发送成功，手机端能看到并打开
- 工具栏和下拉菜单显示插件图标；图标不是空白方块（此项必须在真实 GUI 人工确认）
- 工具栏主按钮无需第二次点击发送；无设备时打开设备管理器并提示手动添加/自动查找
- 多本 EPUB × 多个勾选设备均发送，进度显示当前设备、书名和总任务数
- 发送前显示自动解析进度；部分不可达时仍发送到可达设备，最终结果列出不可达设备
- 地址变化会明确显示且仅用于当次发送，保存地址不会被静默覆盖
- 较大 EPUB 发送过程中 Calibre 界面仍可响应
- 无 EPUB 格式的书籍不会上传，并在最终结果中列出原因
- 发送期间不能重复触发发送任务

### 状态与结果

- 发送进度条最大值为接收设备数 × 可发送 EPUB 数，并随每次上传递增；完成后按钮恢复可用
- 每台设备的成功书目、失败书目和不可达状态统计正确
- 保存设备后，重新打开管理器仍能读取名称、地址、默认和勾选状态
- 完成测试并退出 Calibre 后，检查 `dist/logs/` 中最新日志没有本插件的未处理异常

## 验收结论

以下条件全部满足即可通过：

- `make verify` 成功
- 普通、多本和较大 EPUB 均能在手机端打开
- 无 EPUB、错误地址和服务关闭场景均有可理解的错误提示
- 测试期间 Calibre 没有卡死或崩溃
- 调试日志没有本插件的 traceback

本机现有 `GetFileName.zip` 插件可能产生独立的初始化错误；判断本插件结果时应与“WiFi传书”的日志分开处理。
